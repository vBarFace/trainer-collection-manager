# Screenshot review with offline extraction

## Workflow

In Inventory, choose **Select screenshot** and select one local PNG or JPEG. Read the preview, review automatically filled name/CP/IV suggestions and enter/correct a display name, optional CP, either all three appraisal IVs or none. Each field describes whether it was detected, manually edited, unresolved or unavailable. Review confirms the Pokémon’s data only; classification tags are not selected during import. **Confirm and save** creates a new **Pending** record awaiting appraisal evaluation, without assigning tags. Cancel discards the review. Selecting or cancelling the file picker never writes inventory data. Local OCR reads supported visible name/CP regions; native processing measures segmented appraisal bars. The preview shows while OCR runs and offers cancellation. Fields stay locked until completion. Unreadable/hidden values remain unresolved and manual entry stays usable. See [supported evidence and limitations](local-extraction.md).

Import confirmation does not run evaluation. Users separately select a saved record to request the versioned [appraisal evaluation](evaluation.md). Its Pending, Evaluated, Needs data and Stale states are derived from persistent metadata, current IVs and the supported ruleset, independently of tags. Existing standard/custom assignments remain visible and unchanged. Appraisal findings do not imply strategic analysis or generate classification tags.

The saved list loads from the native repository on entry to Inventory, including after application restart. A failed save retains review values and provenance for correction/retry. A newly selected image resets the entire draft and provenance so values from different screenshots cannot mix. The UI locks submission synchronously while saving; after success it uses the returned committed record without a second fallible read. Matching names/CP/IVs create independent UUIDs. Broad editing, deletion, custom-tag management and filtering remain deferred.

Ordinary import never matches screenshots to existing Pokémon by species, CP, IVs or similarity and never silently updates/merges existing individuals. Saved CP, IV and identity correction starts from the selected UUID and requires explicit confirmation. Future action-specific screenshots must update that selected UUID within its action flow, preserve confirmed lifecycle history, and remain separate from new-individual import. No screenshot-update flow, evolution or Power Up action is implemented in S2.1.

## Correcting saved CP

Select a saved record, choose **Correct saved CP**, then enter a positive whole number or leave the field empty to mark CP unknown. The form begins with the saved value. Confirm explicitly, or choose **Cancel CP correction** to discard it. Saving locks duplicate submissions and uses the native-confirmed result. Recoverable failures keep the draft; a changed or deleted Pokémon requires reloading authoritative inventory information. Switching records discards unsaved corrections.

CP correction preserves the individual's UUID, display name, IVs, identity, tags, creation time and appraisal metadata/results. An actual change updates the modification timestamp and persisted strategic observation revision; a valid no-op preserves both. It does not infer level, actions, costs or strategic usefulness and never runs or invalidates appraisal. See the [native correction and revision contract](../architecture/data-model.md#saved-cp-and-strategic-observations-s21).

## Native boundary and persistence

The import commands registered and enrolled in Tauri's command ACL via `AppManifest` are `select_screenshot` (no path argument), `inventory_snapshot` (no arguments), and `confirm_inventory_import` (typed reviewed fields/tag IDs). Narrow saved-record commands add `evaluate_pokemon`, `correct_pokemon_ivs`, `correct_pokemon_identity` and `correct_pokemon_cp`. Only the local main window receives `inventory-review`; there are no remote capabilities, filesystem/dialog plugins, arbitrary SQL or arbitrary file readers. Database work and image decoding run on blocking workers; a mutex serializes repository access and a native guard prevents concurrent pickers. Tauri injects the calling window as the native dialog parent; no window or path argument is supplied by the renderer.

The existing Rust repository validates names, CP and IV groups. The importer sends an empty `tagIds` list through the unchanged native contract; existing repository tagging APIs remain available and existing assignments are preserved. Its `create_with_tags` method uses one SQLite transaction for a new UUID record and all selected assignments; any validation, assignment or commit failure rolls back. Reads return a consistent snapshot. Migrations 1–5 remain unchanged; S2.1 migration 6 adds only a persisted strategic observation revision and its change triggers. It does not redesign import.

CP crosses IPC as a decimal **string**, or null for unknown, covering 1–9223372036854775807 (SQLite signed 64-bit maximum). JavaScript never converts CP to Number. Tag identifiers are strings too. IVs are a null group or a typed complete object with each integer in 0–15. Incomplete groups and unknown fields are rejected by deserialization, and domain validation remains authoritative. Storage errors are mapped to safe structured codes/messages, never raw SQL or local paths.

## Image limits and privacy

The native picker selects one existing local file, filtered to PNG/JPEG. Content sniffing, not a filename extension, determines the supported codec. Native validation limits encoded input to **10 MiB**, each decoded side to **4096 pixels**, decoded area to **12,000,000 pixels**, and the decoder output-buffer allocation budget to **64 MiB**. The image library also applies this as a best-effort budget to decoder internals; it is not a hard cap on the process working set. Headers are checked before full decoding; actual decode must succeed. A bounded read also handles files that grow after selection. Only PNG/JPEG decoder features are enabled.

A fresh PNG preview is encoded from decoded pixels, stripping source metadata. The preview is reduced to at most 1600 pixels per side. Only preview bytes, original decoded dimensions and typed extraction suggestions/notices and temporary metadata-free text-region PNGs cross IPC. Extraction scans validated full-resolution pixels on the existing blocking worker before downsampling. The source path and filename stay in the picker/read operation and are never returned, logged or persisted. Original files are opened read-only; the application neither copies them into app storage nor modifies/deletes them. SQLite stores only reviewed structured fields and tag assignments. There are no uploads, network services, analytics or image retention.

The renderer holds a temporary Blob URL, revoking it on replacement, picker cancellation, review cancellation, completion or unmount. Late picker results after unmount are discarded. Temporary Rust pixel buffers and file handles are dropped when selection processing returns. The extraction result has no paths/filenames. Temporary OCR crops and raw worker text are discarded after processing, the worker terminates on completion/failure/cancellation/unmount, and persistent worker caching is disabled; the save contract is unchanged. Resource release means dropping references; memory is not cryptographically erased and the OS/native picker may manage its own recent-file history.
