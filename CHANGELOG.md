# Changelog

All notable changes are documented here.

## [Unreleased]

### Changed

- Inventory now distinguishes Pending, Evaluated, Needs data and Stale appraisal states, with record selection and explicit evaluation/re-evaluation. Import review continues to confirm data without tag selection; existing assignments remain intact.

### Added

- First reference-based gym-attack slice (`collection-3`, `gym-attack-1`): optional
  PoGoAPI combat normalization, type-oriented potential and external benchmarks,
  separate owned-alternative priority, and same-UUID roadmap review/comparison.
  Native snapshots resolve identity pins with the active package from the same
  transaction, including cross-instance changes. Catalog-only packages and old
  roadmap JSON remain compatible; no migration or new dependency. See
  docs/development/mvp-gym-attack.md for model and source limitations.

- Deterministic MVP preview: bounded 500-image batch queue with sequential local
  extraction, explicit grouping and idempotent confirmation; inventory search,
  filters, duplicate counts and paged rendering; typed optional manual facts,
  separate favorite/protection and explicit applied-tag editing.
- Rust collection-1 guidance and modeled level-40/50 league statistics with
  explicit uncertainty, actual owned alternatives and optional global goals/
  confirmed Stardust budgets. No battle ranking, universal score or executable
  investment/disposal is invented when mechanics/costs are unsupported.
- Bounded per-UUID roadmap progress, stale context/revision checks, explicit
  confirmation handoffs, current/previous history, and structured user-data export
  excluding screenshots/catalog files. Cross-instance history-only Power Up
  rejects stale optional-observation drafts using an evidence token.
- Windows preview build and volume/end-to-end validation. Broader real-source
  coverage, real-image OCR accuracy and full gameplay acceptance remain open;
  see docs/development/mvp-alpha-validation.md. No release is published.

- Explicit local PvPoke/PokeMiners/PoGoAPI source imports in Settings, with bounded
  conservative normalization, source digests/notices, transactional activation,
  persistent identity/version continuity and rollback. Downloaded game data is
  never bundled. See the MVP coverage matrix for unsupported fields and rights.

- Task 007: offline development-time PvPoke adapter with explicit reviewed species/form mappings, deterministic schema-1 candidates, SHA-256 source/plan/output provenance, cumulative identity/version release ledger and the production Rust validator. Native activation rejects reused species/Dex associations and moved form IDs across in-session removals/provider switches. Fictional transformation, native integration and inventory continuity tests cover updates without changing the database or UI. Real-data distribution remains blocked: source software licenses/public access do not establish the underlying dataset rights; `tcm-empty` / `empty-1` is unchanged.

- Task 006: validated offline reference snapshots with schema/dataset versions and provenance; migration 5 stores explicitly confirmed species/form identity separately from player observations. Stable reference pins, conservative unresolved states, pure evaluation context and a minimal Inventory reference/correction panel prepare future data-backed scopes. No real game dataset is bundled pending verified redistribution rights; original fictional fixtures test the contract. Existing appraisal math and lifecycle are unchanged.

- Confirmed saved-IV corrections from the appraisal panel, with prefilled grouped fields, an explicit unknown-group option, cancellation and retained drafts after save failure. A narrow native command updates only IVs, rejects conflicting saved values and uses existing appraisal invalidation; evaluation and tags are never applied automatically. No schema or ruleset change.

- Task 005: migration 4 persists per-Pokémon appraisal metadata and an IV revision counter. The deterministic `appraisal-1` Rust engine reports confirmed IVs, total, descriptive percentage and a perfect-appraisal finding. Typed findings/recommendation foundations are separate from assigned tags; no strategic recommendations or automatic tag assignments are produced. IV changes and ruleset mismatches invalidate previous attempts.

- Automatic offline screenshot name/CP OCR with bundled English/Portuguese Tesseract resources, temporary native crop preparation, real appraisal-bar palettes/rounded-track support, cancellation/timeout and manual fallback. Verified the supplied real example; no general accuracy rate is claimed.

- Task 004: experimental offline appraisal-bar suggestions, typed field-level provenance and confidence, unresolved notices and editable review. Reset drafts on screenshot replacement. Text OCR remains unavailable; only user-confirmed structured data is saved.

- Task 003: bounded local screenshot preview, manual data review, explicit atomic inventory import and persistent Inventory list. OCR remains deferred.

- Initial Tauri 2 desktop foundation, local SQLite migration infrastructure, quality tooling and project governance documents.
